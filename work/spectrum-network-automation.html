Problem

What wasn’t working

200+ engineers relied on an internal GIS/CAD tool for network design, but the workflow around it was manual: downstream signal recalculation, BOM assembly, and equipment-error checking all depended on someone doing the same repetitive steps correctly, every time.

User Insight

What the user actually needed

The bottleneck wasn't the design tool itself — it was everything engineers did by hand around it. Interviews with 30+ designers kept surfacing the same two time sinks: recalculating signal levels after a change, and manually pulling bills of materials.

My Role

What I owned

  • Functioned as product owner for the internal GIS/CAD network design tool, translating feedback from 30+ users into a prioritized roadmap.
  • Identified manual downstream signal recalculation as a key bottleneck and defined a 3-click Python automation for tracing, recalculation, and verification.
  • Built an Auto BOM function that automatically recorded equipment changes as they happened.
  • Owned the prioritization model for a 30-person cross-functional unit, ranking requests by volume, urgency, and dependency.
  • Led a 20-person audit of 1,000+ optical nodes for DOCSIS 4.0 readiness.
Constraints

What had to be true

  • Any automation had to slot into an existing, already-adopted GIS/CAD workflow — engineers wouldn't switch tools, so the tool had to come to them.
  • Errors in signal recalculation or BOM data have real field consequences, so automation had to be at least as accurate as careful manual work, not just faster.
  • Prioritization had to serve a 30-person cross-functional unit with genuinely competing, legitimate priorities.
Decision Process
01

Finding the bottleneck through interviews

Rather than assuming what to automate, I interviewed 30+ designers about where their time actually went. Manual downstream signal recalculation and BOM/equipment-error checking came up repeatedly, independent of region or seniority.

02

Designing a 3-click automation, not a new system

Because designers wouldn't adopt a separate tool, the automation was built as a lightweight layer that traced, recalculated, and verified signal levels in three clicks inside the existing workflow — cutting recalculation time significantly and manual errors by 25%.

The same logic pattern — trace, compute, verify — was reused for Auto BOM, which recorded equipment changes automatically instead of requiring a manual pull.

03

Scaling adoption

Both tools were rolled out incrementally across regional teams; the recalculation automation was adopted by 3+ regional teams, and Auto BOM went company-wide once report-generation time savings (about 50%) were demonstrated in the first region.

Solution

What shipped

  • A 3-click Python automation for downstream signal tracing, recalculation, and verification, embedded in the existing design workflow.
  • Auto BOM: automatic recording of equipment changes as designers made them, replacing manual bill-of-materials assembly.
  • A prioritization model for the 30-person cross-functional unit that ranked requests by volume, urgency, and dependency instead of first-come-first-served.
Technical Architecture

How it was built

  • Python automation layered on top of the existing GIS/CAD tool's data model, so designers kept their existing workflow and tool of record.
  • Change-tracking hooks that captured equipment modifications at the point of design, rather than reconstructing them later from disparate records.
Product Decisions

Trade-offs I made on purpose

  • Prioritized automating the two highest-frequency manual tasks (signal recalculation, BOM pulling) identified directly from user interviews, over building new design features.
  • Chose incremental regional rollout over a single company-wide launch, using early results to build the case for wider adoption.
Results

What I Learned

Takeaways

  • The highest-leverage product opportunities were hiding inside operational workflows nobody thought of as a “product” — they just looked like how the job was done.
  • Automation that respects an existing workflow spreads faster than automation that asks people to change how they work.
